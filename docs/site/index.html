02 / اولین اتصال

یک بار وارد شو؛ سشن را دوباره استفاده کن.

نمونهٔ بالا یک پیام به "me"، یعنی پیام‌های ذخیره‌شدهٔ خود حساب، می‌فرستد. در اجرای اول شماره و OTP در ترمینال خودتان پرسیده می‌شود؛ کد در ورودی مخفی وارد می‌شود. برای رمزنگاری سشن رمز جداگانه لازم نیست.

اگر حساب سروش ورود دومرحله‌ای فعال دارد، رمز همان حساب هم لازم است. کد ورود و رشتهٔ سشن را در سورس یا لاگ نگذارید. ورود ناموفق، مجوز شروع ثبت‌نام خودکار نیست.

BASH
fnc-splus login personal --data-dir sessions
fnc-splus diagnose personal --data-dir sessions
مقصد در سروش

شناسه‌ها عددی و مطابق قرارداد موتور هستند؛ GUID روبیکا اینجا معتبر نیست. برای شناسهٔ عددی ناشناخته، کش entity و access hash لازم است. username و شیء InputPeer نیز در متدهای کاربردی قابل حل هستند. برای کانال، از شناسهٔ marked برگشتی کلاینت استفاده کنید و آن را حدس نزنید.

02.1 / انتخاب مقصد

chat_id دقیقاً چیست؟

برای پیام‌های ذخیره‌شده "me" بدهید. برای کاربر یا کانال عمومی، نام کاربری واقعی مانند "@your_channel" یا همان نام بدون @ پذیرفته می‌شود. این نام فقط نمونه است؛ با مقصد خودتان جایگزین کنید. برای مقصد عددی، از شناسهٔ برگشتی کلاینت استفاده کنید:

PYTHON
dialogs = await client.get_chats(limit=100)
for dialog in dialogs:
    print(dialog.id, dialog.name)

# عدد را از خروجی واقعی بالا انتخاب کنید.
# مقصد عمومی با نام کاربری هم قابل استفاده است:
sent = await client.send("@your_channel", "سلام")
print("message_id:", sent.id, "chat_id:", sent.chat_id)

نام نمایشی گفتگو الزاماً username نیست. شناسهٔ کانال را از fragment نسخهٔ وب کپی و با افزودن صفرها تبدیل نکنید؛ قرارداد marked ID موتور با نمایش آدرس وب می‌تواند فرق کند. اگر یک عدد هنوز در کش شناخته نیست، ابتدا گفتگوها یا entity آن را از سرور بگیرید.

چرا بعد از اجرای send چیزی چاپ نمی‌شود؟

متد ارسال به‌صورت خودکار شناسهٔ پیام را چاپ نمی‌کند. نتیجه را ذخیره و sent.id و sent.chat_id را چاپ کنید؛ سپس با get_message آن را بازخوانی کنید. هشدار No access_hash in cache … will not catch up دربارهٔ بازیابی تغییرات گذشتهٔ یک کانال است و به‌تنهایی شکست ارسال نیست. مقصد و پاسخ واقعی را بررسی کنید.

03 / احراز هویت پایدار

سشن، محل ذخیره و انتقال

Client("personal", data_dir="sessions") این فایل‌ها را می‌سازد:

sessions/
├── personal.splus encrypted SQLite
├── personal.splus.key AES-256-GCM key
└── personal.splus.lock process lock

نام پیش‌فرض سشن personal و پوشهٔ پیش‌فرض مسیر کاری فرایند است، نه الزاماً پوشهٔ اسکریپت. مسیر را برای سرویس‌های سرور صریح تعیین کنید. سشن مسیر ~ را گسترش می‌دهد و پسوند .splus را در صورت نیاز اضافه می‌کند.

PYTHON
from pathlib import Path
from fnc_splus import Client

BASE_DIR = Path(__file__).resolve().parent
client = Client("personal", data_dir=BASE_DIR / "sessions")
print(client.session_path)

برای انتقال ویندوز ↔ لینوکس، برنامه را متوقف کنید و هر دو فایل .splus و .splus.key متناظر را منتقل کنید. روش آفلاین export زیر، اعتبار ورود، کش و cursorها را منتقل می‌کند؛ inbox/outbox را منتقل نمی‌کند. مقصد باید تازه باشد.

BASH
fnc-splus export-session personal portable/personal.splus --data-dir sessions

فایل lock نیازی به انتقال ندارد و وجودش به‌تنهایی نشانهٔ اجرای فرایند نیست. هر سشن فقط یک مالک همزمان دارد. انتقال یک کلید بدون دیتابیس متناظر یا بالعکس کار نمی‌کند؛ فایل موجود در نبود کلید خودکار بازنویسی نمی‌شود.

اعتبار ورود خصوصی است

دارندهٔ دیتابیس و کلید متناظر به سشن دسترسی دارد. فایل‌ها، StringSession و محتوای صف را در گیت قرار ندهید. کلید مفقود را نمی‌توان از دیتابیس بازیابی کرد؛ ابتدا نسخهٔ پشتیبان متناظر را پیدا کنید.

سشن SPlusthon از قبل دارید؟

دستور import، رشته را به‌صورت مخفی در ترمینال دریافت می‌کند. نیازی به قرار دادن توکن در آرگومان خط فرمان نیست.

BASH
fnc-splus import-session imported --data-dir sessions
04 / پیام‌ها

ارسال، خواندن و پاسخ‌دادن

send و نام جایگزین آن send_message متن ساده می‌فرستند. در حالت معمول یک Message با شناسهٔ سرور برمی‌گردد. متدهای کاربردی پارامتر parse_mode ندارند؛ برای entity و markup از RPC و نوع‌های TL استفاده کنید.

PYTHON
first = await client.send("@your_channel", "سلام از FNC-Splus")
print(first.id, first.chat_id)
reply = await client.send("@your_channel", "پاسخ", reply_to_message_id=first.id)
forward = await client.forward_message("@your_channel", first.id, "me")

saved = await client.get_message("@your_channel", first.id)
print("بازخوانی از سرور:", saved is not None)
history = await client.get_messages("@your_channel", limit=20)

get_messages(ids=...) برای یک شناسه معمولاً یک Message و برای چند شناسه فهرست برمی‌گرداند؛ پیام حذف‌شده ممکن است None باشد. بدون ids، تاریخچهٔ محدود با پیش‌فرض ۲۰ پیام خوانده می‌شود. فوروارد کاربردی یک پیام را منتقل می‌کند؛ ارسال چندتایی در مرجع RPC در دسترس است.

متن قالب‌دار با entity

PYTHON
from fnc_splus import types

result = await client.messages_send_message(
    peer=types.InputPeerSelf(),
    message="Hello",
    random_id=123456789,  # برای هر ارسال تازه مقدار یکتا بسازید
    entities=[types.MessageEntityBold(offset=0, length=5)],
)

offset و length در MessageEntityها بر پایهٔ واحدهای UTF-16 هستند؛ برای متن دارای ایموجی طول پایتون را بدون تبدیل مبنا قرار ندهید. در نمونهٔ بالا متن ASCII است.

هر رسانه، با مسیر روشن

PYTHON
await client.send_photo("me", "photo.jpg", caption="کپشن عکس")
await client.send_video("me", "video.mp4", caption="کپشن فیلم")
await client.send_file("me", "document.pdf", caption="فایل")
await client.send_voice("me", "voice.ogg", duration=4)
متدرفتارنکته
send_photoاصلاح جهت EXIF، تبدیل به JPEG و محدودکردن ضلع بزرگ به ۲۵۶۰ پیکسلتامنیل مستقل در InputMediaUploadedPhoto وجود ندارد؛ پیش‌نمایش را سرور می‌سازد.
send_videoخواندن مدت و ابعاد، ساخت و آپلود تامنیل JPEG تا ۳۲۰ پیکسلبایت‌های فیلم transcoding نمی‌شوند؛ برای وب از MP4 سازگار H.264 استفاده کنید.
send_voiceسند با نوع audio/ogg و ویژگی voiceduration را بر حسب ثانیه بدهید؛ فایل تبدیل به OGG نمی‌شود.
send_fileارسال سند با MIME، attribute و thumbnail اختیاریمسیر باید فایل موجود باشد؛ برای عکس و ویدئوی قابل نمایش از متد تخصصی استفاده کنید.

دانلود رسانهٔ یک پیام

PYTHON
message = await client.get_message(chat_id, message_id)
if message is None:
    print("پیام پیدا نشد")
elif message.media:
    path = await client.download(message, "downloads/media.bin")
    print(path)
else:
    print(message.message or "")

download و download_media یک رفتار دارند. با مقصد مسیر، پوشهٔ والد ساخته می‌شود؛ بدون مقصد، نام/مسیر انتخابی موتور برمی‌گردد. برای پیام متنی، متن از message.message یا delivery.text خوانده می‌شود؛ دانلودی وجود ندارد.

06 / چند رسانه، یک آلبوم

عکس‌ها و فیلم‌ها را کنار هم بفرست.

send_album فهرست ۲ تا ۱۰ عکس/ویدئو می‌گیرد. آلبوم با یک درخواست مشترک ارسال می‌شود و فهرست Messageها به ترتیب ورودی برمی‌گردد. برای ویدئو افزونهٔ [video] لازم است.

PYTHON
photos = await client.send_album("me", ["photo1.jpg", "photo2.jpg"], caption="عکس‌ها")
videos = await client.send_album("me", ["video1.mp4", "video2.mp4"], caption="فیلم‌ها")
mixed = await client.send_album("me", ["photo.jpg", "video.mp4"], caption="آلبوم ترکیبی")
print([message.id for message in mixed])

caption متن مشترک را روی عضو اول قرار می‌دهد. به‌جای آن می‌توانید captions با یک رشته برای هر عضو بدهید؛ این دو گزینه همزمان پذیرفته نمی‌شوند.

PYTHON
await client.send_album(
    "me", ["photo.jpg", "video.mp4"],
    captions=["کپشن عکس", "کپشن فیلم"],
    reply_to_message_id=123,

نتیجهٔ تست واقعی

آلبوم دو عکس، دو فیلم H.264 و ترکیبی در Saved Messages ارسال و بازخوانی شدند؛ شناسهٔ گروه مشترک، ترتیب، کپشن، پیش‌نمایش و دانلود قابل بازشدن هر شش فایل بررسی شد. وب رسمی نیز هر سه گروه را آلبوم نشان داد. کپشن‌های جداگانه روی سرور حفظ می‌شوند، اما نسخهٔ وب در آلبوم ترکیبی فقط کپشن عضو آخر را زیر مجموعه نمایش داد.

آماده‌سازی و آپلود اعضا قبل از ثبت درخواست نهایی در outbox انجام می‌شود. اگر این مرحله خطا دهد، ممکن است فایل آپلودشده روی سرور باقی بماند اما پیام آلبوم هنوز ثبت نشده باشد. یک عضو نامعتبر به آلبوم تک‌فایلی تبدیل نمی‌شود.

07 / دریافت زنده

رویداد را دریافت کن؛ پردازش را پایدار نگه دار.

callback با دو آرگومان (client, delivery) اجرا می‌شود. نام‌های message، messages و new_message یا خود کلاس events.NewMessage پذیرفته می‌شوند؛ نمونهٔ ساخته‌شدهٔ آن را به این decorator ندهید.

PYTHON
import asyncio
from fnc_splus import Client

SOURCE_CHAT_ID = -1001234567890  # مقدار واقعی را از dialog.id بگیرید
client = Client("personal", data_dir="sessions", auto_login=False)

@client.on("message", chats=SOURCE_CHAT_ID)
async def receive(client, delivery):
    print(delivery.chat_id, delivery.message_id, delivery.text)
    print("reply:", delivery.reply_to_message_id)
    if delivery.message.media:
        await client.download(delivery.message, f"downloads/{delivery.message_id}.bin")

async def main():
    async with client:
        await client.run()

asyncio.run(main())

فیلتر chats یک شناسهٔ marked عددی یا مجموعهٔ آن‌هاست؛ رشتهٔ عددی پذیرفته می‌شود، username در این فیلتر پذیرفته نمی‌شود. incoming=True فقط ورودی، False فقط خروجی و None هر دو را انتخاب می‌کند. برای پست کانال پیش از فعال‌کردن فیلتر incoming، مقدار واقعی out را بررسی کنید.

پیام قبل از callback در inbox رمزنگاری‌شده ذخیره می‌شود. با پایان موفق handler، رویداد done می‌شود؛ خطای callback با وقفه دوباره تحویل داده می‌شود. تضمین تحویل «حداقل یک بار» است. برای کار بیرونی مانند relay، شناسهٔ رویداد و نگاشت پیام/operation را در برنامه ثبت کنید تا تکرار callback، پست تکراری نسازد.

مرز پوشش رویداد

inbox پایدار فقط پیام جدید را پوشش می‌دهد. آلبوم به شکل پیام‌های جدا با grouped_id مشترک می‌رسد؛ collector آمادهٔ آلبوم در این لایه وجود ندارد. ویرایش/حذف و builderهای دیگر از client.native قابل استفاده‌اند و inbox FNC را دور می‌زنند. catch-up به cursor، access hash و محدودیت سرور وابسته است.

run(workers=1) تا قطع اتصال یا پایان worker منتظر می‌ماند. چند worker در این نسخه پذیرفته نمی‌شود؛ callbackها مرتب اجرا می‌شوند. همهٔ handlerهای ثبت‌شده در یک تلاش اجرا می‌شوند؛ اگر handler بعدی شکست بخورد، تلاش مجدد می‌تواند handler قبلی را هم دوباره اجرا کند.

08 / کنترل ارسال

timeout به معنی «نرسیدن پیام» نیست.

PYTHON
from fnc_splus import OperationUnknownError

queued = await client.send("me", "ارسال پایدار", wait=False)
operation_id = queued.operation_id  # در دیتابیس برنامه نگه دارید
try:
    message = await client.wait_operation(operation_id, timeout=60)
    print(message.id)
except (TimeoutError, OperationUnknownError):
    operation = await client.get_operation(operation_id)
    print(operation.state, operation.error)
    # ابتدا نتیجه یا مقصد را بررسی کنید؛ ارسال تازه نسازید.
وضعیتمعنی و اقدام مناسب
queuedدرخواست پایدار ثبت شده و منتظر worker است؛ پس از restart اجرا می‌شود.
sendingworker در حال فراخوانی سرور است؛ در وقفهٔ مبهم نتیجه unknown می‌شود.
doneپاسخ سرور ذخیره شده است؛ result را بررسی کنید.
failedرد قطعی یا رسانهٔ غیرقابل استفاده؛ علت را اصلاح کنید.
unknownممکن است سرور درخواست را اجرا کرده باشد؛ مقصد را بررسی کنید و کورکورانه دوباره نفرستید.

timeout ارسال کاربردی، زمان انتظار نتیجهٔ صف است؛ زمان resolve، تبدیل تصویر یا آپلود را محدود نمی‌کند. پایان انتظار worker را لغو نمی‌کند. random_id و درخواست نهایی در صف حفظ می‌شوند. ارسالِ interrupted خودکار بازپخش نمی‌شود. inbox/outbox خودکار پاک‌سازی نمی‌شوند؛ برای سرویس طولانی اندازهٔ دیسک را پایش کنید.

خطامعنی
LoginRequiredErrorبا auto_login=False، سشن مجاز موجود نیست؛ یک بار در ترمینال وارد شوید.
SessionRevokedErrorسرور اعتبار سشن موجود را رد کرده است؛ تکرار خودکار OTP انجام نمی‌شود.
SessionInUseErrorفرایند دیگری مالک همین سشن است.
SessionErrorمشکل فایل، کلید یا رمزگشایی سشن؛ جفت فایل‌ها را بررسی کنید.
AuthenticationRequiredکلاس پایهٔ خطاهای نیاز به احراز هویت در FNC.
OperationFailedErrorعملیات قطعاً رد شده است.
OperationUnknownErrorنتیجه یا نگاشت پیام نامطمئن است.
UnsupportedMediaErrorسرور رسانهٔ قابل استفاده نداده؛ یک placeholder ممکن است ایجاد شده باشد.
TimeoutErrorانتظار تمام شده؛ همان operation_id را بررسی کنید.

خطاهای خام ارائه‌دهنده از fnc_splus.errors صادر می‌شوند. در صف، نوع خطای سرور در Operation.error ثبت و به خطای FNC تبدیل می‌شود؛ در خواندن مستقیم ممکن است خود RPCError دریافت شود.

09 / مرجع پروتکل

یک عملیات؛ سه روش فراخوانی

PYTHON
from fnc_splus import types

# هر سه خط، همان RPC را فراخوانی می‌کنند؛ یکی را انتخاب کنید.

همهٔ روش‌ها به Catalog همین نسخه می‌رسند. متدهای marked read در پیاده‌سازی مستقیم اجرا می‌شوند و باقی در outbox ثبت می‌شوند. برچسب «مستقیم» توصیف مسیر پیاده‌سازی است؛ برخی عملیات خواندنی پرچم‌های تغییردهنده دارند، مانند افزایش بازدید. پاسخ خام، شیء TL است؛ ارسال RPC خام الزاماً Message آماده برنمی‌گرداند.

مرجع کامل ۳۷۴ عملیات برای هر مورد توضیح فارسی، امضای واقعی پایتون، فیلدهای اجباری و پیش‌فرض، نوع TL، نوع خروجی، مثال سه روش و طرح باینری دارد. مرجع سازنده‌ها نوع‌های پیچیده مانند InputPeer و InputMedia را توضیح می‌دهد.

RPC با پشتیبانی قابلیت فرق دارد

پرداخت، تماس، استوری، پریمیوم و تنظیمات حساب در طرح حضور دارند اما تست حساب واقعی برای همهٔ آن‌ها انجام نشده است. RPC تماس، موتور صوت/تصویر نیست. متدهای handshake مانند req_pq و destroy_auth_key توسط Client.invoke رد می‌شوند؛ مذاکرهٔ کلید را به موتور بسپارید.

PYTHON

وقتی نتیجه مطابق انتظار نیست

ModuleNotFoundError یا ناشناخته‌بودن پکیج در VS Code

با همان مفسری که اسکریپت را اجرا می‌کند، python -m pip show FNC-Splus را بررسی کنید. محیط .venv را در Python: Select Interpreter انتخاب و پنجره را reload کنید. نام import باید fnc_splus باشد.

انتقال سشن از ویندوز به لینوکس

هر دو فایل دیتابیس و کلید متناظر را پس از بستن برنامه منتقل کنید. از export آفلاین استفاده کنید؛ keyring لازم نیست. مالکیت و مجوز فایل روی لینوکس باید به کاربر اجرای سرویس اجازهٔ خواندن و نوشتن بدهد.

فیلم در وب پخش نمی‌شود، با اینکه ارسال شده

send_video کدک را تبدیل نمی‌کند. فایل MP4 با H.264 سازگار انتخاب کنید؛ پسوند به‌تنهایی کدک را مشخص نمی‌کند. سرور و مرورگر هر دو باید رسانه را پشتیبانی کنند.

پیام کانال در ایونت دریافت نمی‌شود

عضویت و دسترسی، شناسهٔ marked، فیلتر incoming و access hash کش را بررسی کنید. ابتدا نمونهٔ read-only get_messages را اجرا کنید. روی ایونت‌های ویرایش/حذف یا یک collector آمادهٔ آلبوم در inbox فعلی حساب نکنید.

بعد از timeout دوباره ارسال کنم؟

ابتدا همان operation_id را با get_operation و wait_operation بررسی کنید. در وضعیت unknown، مقصد را بخوانید؛ ارسال تازه می‌تواند پیام تکراری بسازد.

آیا همهٔ ۳۷۴ متد روی حساب اجرا شده‌اند؟

خیر. همه در طرح منبع و تست باینری محلی پوشش دارند؛ عملیات حساس یا تغییر حساب فقط برای افزایش پوشش اجرا نشده‌اند. برچسب تست هر مورد و بخش محدودیت‌ها را ببینید.
