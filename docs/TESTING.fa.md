# گزارش تست FNC-Splus ۰٫۱٫۰

تاریخ: ۲۰۲۶-۱۰-۱۸. این گزارش تفاوت بررسی سورس، تست پروتکل بدون حساب و تست واقعی حساب را حفظ می‌کند.

## آزمون‌های خودکار

۴۲۵ تست در Windows با Python ۳٫۱۴ و همان ۴۲۵ تست در Ubuntu با Python ۳٫۱۴ پاس شده‌اند؛ هیچ تستی skip نشده است. گزارش شمارش هر محیط در `validation.json` ثبت شده است. CI برای Windows/Ubuntu و Python ۳٫۱۱/۳٫۱۴ تعریف شده است؛ تا پیش از اجرای GitHub Actions، گذر تمام خانه‌های آن ماتریس ادعا نمی‌شود.

- برای هر ۳۷۴ نام RPC رسمی، درخواست با دادهٔ مصنوعی ساخته، چیدمان فیلدها با encoder مستقل مبتنی بر TL رسمی تطبیق و decode/encode دوباره بررسی می‌شود. هیچ‌یک از عملیات حذف، پرداخت یا مدیریت حساب برای این پوشش روی سرور اجرا نمی‌شوند.
- شماره‌های فارسی/عربی و قالب‌های ایران، OTP نامعتبر با سقف سه تلاش و فقط یک درخواست کد، callback ورود دومرحله‌ای حساب، سشن موجود بدون پرسش، سشن لغوشده و تفاوت خطای شبکه/۵۰۰ با رد احراز هویت بررسی می‌شوند.
- رمزنگاری و AAD، کلید مفقود/نادرست، قفل مالکیت، export/import و StringSession، کش entity و cursor دریافت تست می‌شوند.
- ثبت پایدار عملیات، timeout بدون ارسال دوباره، نتیجهٔ نامطمئن، cancellation و restart، متدهای sync و native namespace، caption، reply، forward، metadata ویدئو و تامنیل تست می‌شوند.
- دریافت پیامِ ماندگار، dedup، تحویل مجدد callback ناموفق، frameهای تکه‌شدهٔ WebSocket، بسته‌شدن اتصال، لغو اتصال و آزادشدن منابع HTTP و انتخاب فایل‌سرور بررسی می‌شوند.

## تست واقعی بدون حساب

هر چهار WebSocket استخراج‌شدهٔ `im-server` و `im-server-1/-2/-3` با subprotocol باینری و درخواست PQ پاسخ دادند؛ nonce جواب با درخواست تطبیق داشت. اتصال اصلی HTTP `/apiw1` با POST خالی پاسخ ۴۰۴ داد. حضور مسیر در سورس به معنی عملیاتی بودن fallback نیست.

## تست واقعی با اجازهٔ مالک حساب

ورود شماره/OTP در ترمینال خود کاربر انجام شد؛ شماره، OTP، StringSession، کلید و دادهٔ حساب در گزارش عمومی نیستند.

| تست | نتیجه |
|---|---|
| ورود واقعی با شماره و OTP | موفق |
| بستن و بازکردن سشن، سه بار بدون OTP | موفق |
| انتقال آفلاین سشن Windows → Linux و بررسی مجازبودن در سرور واقعی | موفق، بدون OTP و بدون ارسال پیام |
| متن، بازخوانی از سرور | موفق در پیام‌های ذخیره‌شده |
| ریپلای و تطبیق شناسهٔ والد | موفق در پیام‌های ذخیره‌شده |
| عکس با کپشن، بازخوانی و دانلود قابل decode | موفق |
| ویدئو با کپشن و تامنیل، بازخوانی و دانلود قابل decode | موفق |
| ویدئوی H.264 سازگار با مرورگر | ارسال، بازخوانی و دانلود قابل decode موفق |
| فوروارد پیام آزمایشی خودمان به Saved Messages | موفق |
| ایونت زندهٔ پیام ارسالی از وب‌کلاینت، تحویل از inbox پایدار | موفق |
| نظرسنجی در Saved Messages | سرور تأیید داد ولی رسانهٔ poll نداد؛ وب رسمی پیام پشتیبانی‌نشده نشان داد. `UnsupportedMediaError` گزارش می‌شود و دوباره ارسال نمی‌شود |

تمام ارسال‌های این بخش فقط در پیام‌های ذخیره‌شدهٔ همان حساب انجام شدند. شناسهٔ عملیات پیش از انتظار برای جواب در journal تست ذخیره شد؛ پس از اصلاح مسیر آپلود، متن‌ها دوباره فرستاده نشدند. عکس و ویدئو فایل‌های مصنوعی آزمایش بودند؛ فایل شخصی کاربر ارسال نشد.

## محدودیت‌های باقی‌مانده

تست واقعی گروه، کانال، مدیریت حساب، ربات، پرداخت، تماس، آلبوم، نظرسنجی در گروه/کانال و ویس در این دور انجام نشده است. سشن پایدار و reopen بین دو سیستم‌عامل تأیید شد؛ اجرای چندروزهٔ سرویس در تولید هنوز اندازه‌گیری نشده است. پوشش نام‌ها یا تست serializer، تضمین مجوز یا پشتیبانی سرور از همهٔ قابلیت‌ها نیست.

پیام جدید از WebSocket دریافت می‌شود. بازیابی فاصلهٔ قطعی تابع وضعیت MTProto، access hash موجود و محدودیت سرور است. رفتار صف و callbackها به معنای تضمین «دقیقاً یک بار» در تمام crashها نیست. اندازهٔ داده‌های پایدار خودکار محدود نمی‌شود.

## بازتولید

```bash
python -m pip install ".[dev,video]"
python -m pytest
python -m ruff check src scripts tests
python -m build
python scripts/probe_public.py
```

اسکریپت‌های `live_login.py`، `live_saved_messages.py`، `live_events.py` و `live_h264.py` با تست معمول pytest اجرا نمی‌شوند. فقط با حساب و مقصد آزمایشی مجاز و پس از بررسی توضیح اسکریپت اجرا شوند. فایل‌های سشن، گزارش‌های خصوصی و fixtureهای دانلودشده در `test-results` هستند و در گیت یا wheel قرار نمی‌گیرند.
